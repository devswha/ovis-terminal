# Identity transitions

Which identity a client may keep across each cause (plan todo 48; IDEAL-045,
IDEAL-094, IDEAL-099). The table below is generated by
`ovis_terminal_protocol::domain::restart::identity::markdown()`; a protocol test
fails when this copy differs.

| cause | machine_id | runtime_lifetime | server_boot_id | terminal_id | terminal_incarnation | process_incarnation | stream_id | seq |
|---|---|---|---|---|---|---|---|---|
| control_restart | kept | kept | replaced | kept | kept | kept | replaced | advances |
| core_crash | kept | kept | replaced | kept | kept | kept | replaced | advances |
| holder_loss | kept | kept | kept | kept | replaced | replaced | replaced | advances |
| upgrade | kept | kept | replaced | kept | kept | kept | replaced | advances |
| host_reboot | kept | replaced | replaced | kept | replaced | replaced | replaced | rescoped |

- `kept`: the same value names the same thing afterwards.
- `replaced`: a new value is minted; the old one never names anything again.
- `advances`: the event sequence continues above its last value in the same lifetime.
- `rescoped`: a new sequence domain starts under the new lifetime; old cursors
  report `lifetime_mismatch`.

## Rules

- A process incarnation is `kept` only when the successor control proves it with the
  same PID and start token the holder reported at spawn. A restored record is never
  proof (RT-HD-05): after a host reboot terminals return as `restored_metadata` or as
  `relaunched` with a new incarnation.
- The runtime lifetime survives a control restart because the successor reads it from
  the persisted restart intent. It is never inferred from a cached endpoint
  descriptor or an earlier `hello` reply. An intent written under another host boot
  is refused as `host_rebooted`.
- `server_boot_id` changes on every control restart, so a client compares `hello`
  results (`listen::continuity`) to tell a restart apart from a new lifetime.
- Attach streams never survive a boundary. Streams of the old boot end with
  `server_restart` (`TerminalStreams::restarting`), and connections of the old boot
  close with `$/closing{reason: "server_restart", incarnations_preserved: true}`
  (`ServerHandle::restart`), never `server_shutdown`. A client reconnects to the same
  endpoint, re-attaches and gets a new `stream_id` for the same process incarnation.
- An incarnation held when the restart began that the successor cannot prove is
  reported lost with typed evidence (`exited` with code or signal, `exit_unknown`,
  `gone`, `replaced` with the identity found, `not_adopted`), never as preserved.
- `Control::open` reports `planned` only when a restart intent was on disk; without
  one it reports `unplanned` and claims no handover.

## Interrupted work

`server.restart` lists the operations that were in flight when the boundary
started. Each is classified from the committed ledger and holder write evidence
only:

| ledger state at the boundary | outcome |
|---|---|
| committed | `committed`; the retained result is returned by `op.get` |
| accepted, never started | `not_started`; repeating the same `op_id` is safe |
| failed / cancelled | `failed` / `cancelled` |
| running, or outcome unknown | `outcome_unknown` with `delivery: written` (bytes written and the output cursor) when the holder acknowledged the write, else `delivery: unproven`; it is never repeated automatically |

A wait armed at the boundary ends `cancelled` with the output offset a new wait
resumes from. It never ends as `timeout` or as a match.

## Administrative verbs stay separate

| verb | programs | receipt |
|---|---|---|
| `server.restart` | kept | old and new boot, preserved incarnations, interrupted operations |
| `server.stop {scope: control_only}` | kept | preserved incarnations, nothing ended |
| `server.stop {scope: control_and_programs}` | ended | ended incarnations, plus any whose exit stayed unproven |
| `terminal.kill` | one process | delivered stages and reaped exit evidence |
| `terminal.rm` | none | historical incarnations whose metadata was removed |

`server.stop` has no default scope: an unknown or missing scope is
`invalid_params` at `params.scope`, and nothing stops.
