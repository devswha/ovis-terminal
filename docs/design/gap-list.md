# ovis-terminal gap list

This document lists every gap between today and [the ideal state](ideal-state.md). Today means an empty ovis-terminal repository, with Ovis running on herdr 0.9.5 and hc 0.1.14.

## Summary

- Total: 150 gaps. By severity: 12 blocker, 77 high, 52 medium, 9 low.
- Blocker means Ovis cannot work without it. High means Ovis carries a workaround today. Medium means quality or latency. Low means polish.
- Biggest blocker 1 is GAP-004. herdr has no persistent multiplexed connection, because it answers one frame and closes (RT-HD-01).
- Biggest blocker 2 is GAP-038. ovis-terminal has no PTY host or structured launch, so there is no terminal to attach to (NEED-065).
- Biggest blocker 3 is GAP-020. No subscription returns a snapshot at revision R followed only by later changes, so startup has a blind interval (NEED-044).
- Only five ideal properties are already met by herdr or hc (see Not gaps). Even those still have to be built in ovis-terminal, because the repository holds no runtime code.

## Not gaps

These ideal properties are already satisfied by herdr 0.9.5 or hc 0.1.14 as observed or catalogued. ovis-terminal still has to carry each design forward.

- **IDEAL-003:** hc rejects an incompatible protocol generation before acting (CAT-3190). The herdr CLI aborts on a version mismatch before sending the request (CAT-583).
- **IDEAL-005:** herdr 0.9.5 and hc echo the request ID with exactly one result or error per accepted request (NEED-004, RT-HC-06). The legacy ID problem in older herdr is tracked as a gap row citing NEED-005.
- **IDEAL-006:** hc's framed protocol separates JSON control from terminal bytes with a nine-byte channel/kind/length header (CAT-3166).
- **IDEAL-026:** waits are satisfied immediately when the installed filter already matches current state (CAT-107, CAT-3211).
- **IDEAL-098:** hc `doc.get` and `doc.set` provide versioned compare-and-swap documents with change events (CAT-3228, CAT-3229, CAT-3231).
