fix(client-ts): map every schemars component name to a TypeScript identifier and check the generated SDK in CI

Closes GAP-REGRESSION (a defect that landed at the T29/T55 seam). Delivers IDEAL-115 (SDK parity) for the current integration schema.

T55's `terminal.process_info` added schemars generic components (`Observed_Array_of_ProcessSample`, `Observed_ProcessSample`, `Observed_Array_of_string`, `Observed_string`), and the T29 generator refused them. What changed:

- `scripts/codegen/render.ts`: `typeName(component)` splits the component name on runs of characters other than `[A-Za-z0-9]` and upper-cases the first letter of each word, so `Observed_Array_of_ProcessSample` becomes `ObservedArrayOfProcessSample`. A name that is already PascalCase maps to itself, so every component that existed before keeps its TypeScript name. If the result is not `^[A-Z][A-Za-z0-9]*$` (for example `9Lives` or `__`), the name is refused with `unsupported_schema`. Identifier validation is still in place. `refName` uses the same mapping, so declarations and references always agree. `GenerateError` now has one hint per kind and carries `target` and `sources` on `name_collision`.
- `scripts/codegen/modules.ts`: the collision check runs on the mapped names (including the generated `<Name>Values` constants). It throws `name_collision`, naming both source components and the shared target.
- `src/generated/`: regenerated by `bun run generate`, with no hand edits. It adds `methods/credential.ts` (T57) and `terminal.process_info` (T55) with the `Observed*` components, and refreshes the `openrpc.json` copy and digest headers.
- `.github/workflows/ci.yml`: one new job, `client-ts`, on an ubuntu-24.04 + macos-15 matrix. It pins the C toolchain the same way the `test` job does, uses Rust 1.99.1 and builds the two fixture binaries. It then runs `bun install --frozen-lockfile`, `bun run generate:check`, `bun run typecheck` and `bun test` with bun 1.4.3. No other job was touched.

## Contract checklist

1. u64 on the wire: unchanged. Decimal components still render as `Decimal<"Name">`, and the regenerated `Observed*` and `ProcessSample` types keep `ProcessPid` and `StartToken` as branded types.
2. Errors: TypeScript has no thiserror. The generator's boundary error is `GenerateError`, with a closed `kind` union and a hint per kind (`unsupported_schema`, `name_collision`, `stale_output`), plus `target`/`sources` on collisions.
3. Identities: unchanged. Named string components stay `Id<"Name">`, now keyed by the mapped name.
4. Tests assert behaviour: generated declarations, references and typed error kinds and fields. They do not check prose.
5. No lint suppression, no placeholder TODOs, no hand-edited generated files.
6. Holder wire generation is unchanged (2), and no Rust code changed.

## Seams

- No Rust or public API change. The mapping only renames the TypeScript names of components whose schema names were not identifiers (the four `Observed_*` components, which no client code referenced because they could not be generated before).
- `.github/workflows/ci.yml`: one new job only.

## Risks

- A future schema rename that makes two components map to the same name (for example `Foo_Bar` next to `FooBar`) now fails generation with `name_collision`, which also fails `generate:check` in CI. That outcome is intended.
- The `client-ts` job builds two debug binaries per OS, which takes several minutes of runner time. It shares `Swatinem/rust-cache`.
