# Cargo manifest scope decision (task 3)

The plan's write scope for todo 3 lists `crates/ovis-terminal-protocol/src/rpc/`,
`src/errors/`, `tests/rpc.rs` and the task-3 scenario, but not the crate
manifest. The scaffold manifest declared no dependencies, so `serde`,
`serde_json` and `thiserror` (all pinned in `[workspace.dependencies]`) could not
be used and the crate did not compile (see `tdd-red.log`).

Resolution: the orchestrator steer ruled that "the crate manifest is a
dependency seam" and that the `proptest` dev-dependency is in scope. Under that
ruling `crates/ovis-terminal-protocol/Cargo.toml` gained workspace-inherited
`serde`, `serde_json`, `thiserror` and dev-dependencies `proptest`, `serde_json`.
`Cargo.lock` was regenerated by Cargo (`Locking 49 packages`); no version was
hand-edited.

Also outside the literal scope, forced by the 250 pure-LOC hygiene gate:
`tests/rpc_counter.rs` and `tests/rpc_errors.rs` split off from `tests/rpc.rs`
by responsibility (counter encoding, error wire shape). The plan's named QA
targets `--test rpc happy|failure` are unchanged.
