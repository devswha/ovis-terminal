# GAP-152 cursor model: recorded as still open by todo 85

Decision: todo 85 does not change the authoritative VT cursor. GAP-152 stays partly open for
multi-row images (note updated in `docs/design/traceability.json`).

Reasons:
1. Moving the cursor past a placement (Kitty `a=T` without `C=1`, iTerm2 `File=` to the next line,
   sixel per DECSDM) changes where every later printed character lands, i.e. the cell semantics
   of non-image cells. The todo 85 block forbids that ("Must NOT: change existing cell semantics
   for non-image cells").
2. The advance is only computable from the header when the extent is declared in cells (Kitty
   `c=`/`r=`, iTerm2 `width=N;height=N` in cells). For a Kitty image without `c`/`r`, an iTerm2
   image with `auto`/pixel/percent sizes, or any sixel, the advance depends on the image's pixel
   size and the client's cell pixel size, which the headless runtime never learns (it decodes no
   payload and answers no XTWINOPS cell-size query from a real renderer). A partial advance would
   trade one cursor mismatch for another and break paint/checkpoint equivalence tests that compare
   a replayed engine with a continuous one.

What todo 85 does deliver for that situation: a screen read reports each stored image by the
cells it covers while it is intact; when text overwrites a placement (the GAP-152 symptom) the
placement is released and the read reports no placeholder, which matches what the VT holds.
